# K-FOOD 게임천국 🕹️

K-Food 박람회 **PC방 컨셉 부스**용 아케이드 웹앱. 게임에서 점수를 올리면 등급(S~D)이 나오고, 부스 직원이 확인해 음식 포인트로 교환해주는 흐름을 위해 만들었습니다.

## 기술 스택

| | |
|---|---|
| 빌드 | Vite 5 + TypeScript (strict) |
| UI | React 18 + React Router 6 |
| 애니메이션 | Framer Motion 11 (3D 틸트 카드, 페이지 전환, 스태거 리스트) |
| 게임 렌더링 | Canvas 2D — 프레임워크 없는 순수 게임 루프 |
| 아트 | 픽셀아트 K-푸드 스프라이트 12종 (전체 300KB) + 코드로 그린 벡터 폴백 |
| 물리 | matter-js 0.20 (K-푸드 타워 전용, 2D 강체) |
| 사운드 | Web Audio API 실시간 합성 (음원 파일 없음) |
| 배포 | Vercel (`vercel.json` 포함, SPA 리라이트 설정됨) |

## 실행

```bash
npm install
npm run dev        # 개발 서버 (http://localhost:5173)
npm run build      # 타입체크 + 프로덕션 빌드 → dist/
npm run preview    # 빌드 결과 로컬 확인
```

### Vercel 배포

이 저장소를 Vercel에 연결하면 별도 설정 없이 자동 빌드됩니다 (Framework: Vite, Output: `dist`).
CLI로 할 경우:

```bash
npx vercel --prod
```

부스에서는 배포된 URL을 브라우저로 열고 **F11**로 전체화면을 권장합니다.

## 게임

### 🏃 네온 러너 (`/runner`)
장애물이 개별이 아니라 **동작 콤보 패턴 단위**로 나오는 리듬형 러너.

- **조작**: `SPACE` 점프 / 공중에서 한 번 더 = 2단 점프, `↓` 숙이기 / 공중에서 = 급강하
- **장애물**: 블록(점프), 높은 벽(2단 점프), 드론(숙이기), 높은 드론(페이크), 낮은 천장(구간 내내 숙이기)
- 속도 3티어로 패턴 풀이 어려워지고, 간격은 속도에 비례 확대되어 리듬 간격(0.3~0.45초)이 유지됨
- BGM 템포가 주행 속도에 연동됨

### 🚀 벡터 스트라이크 (`/shooter`)
**15웨이브 + 최종보스**로 끝이 있는 종스크롤 슈팅. 수학 공식으로 적 패턴을 구성했습니다.

| 패턴 | 공식 |
|---|---|
| 사인파 편대 | `x(t) = x₀ + A·sin(ωt + φ)` — 위상차로 편대 지그재그 |
| 나선 진입 | 극좌표 `(r·cosθ, r·sinθ)`, 반경 지수 수렴 + 타원 압축 |
| 조준탄 / 돌진 | 벡터 정규화 `(P−E)/‖P−E‖` |
| 링 탄막 | 원 n등분 `vᵢ = spd·(cos 2πi/n, sin 2πi/n)`, 매 발사 반 칸 회전 |
| 유도 미사일 | 각도차 `[−π,π]` 정규화 후 각속도 제한 조향 |
| 최종보스 이동 | 리사주 곡선 `x=A·sin(at)`, `y=B·sin(bt+δ)` |

- **조작**: 마우스 이동(지수 보간 추적) 또는 방향키, 사격 자동
- **무기 강화**: `P` 아이템으로 Lv.1(단발) → Lv.5(5방향 고속연사). **피격 시 1단계 하락**
- **최종보스**: HP 3단계 페이즈 — 회전 링 → 양방향 나선 스트림 → 이중 링 + 유도미사일
- 격파 시 **MISSION CLEAR** + 보너스 5,000점 + 남은 목숨당 2,000점

### 🍢 K-푸드 타워 (`/tower`)
접시 위에 음식을 쌓는 **물리 기반** 게임. 게임 로직이라 부를 만한 게 거의 없습니다 — 재미의 원천을 코드로 만들지 않고 강체 물리에 위탁했습니다.

- **모드**: `1` 혼자(무너질 때까지 쌓기 → 점수·등급) / `2` 둘이(번갈아 쌓고 먼저 떨어뜨린 쪽 패배)
- **조작**: `←→` 이동, `↑`·`↓` 회전(시계/반시계), `SPACE` 놓기 — 터치 기기는 드래그 + 화면 하단 `회전`·`놓기` 버튼
- **`G` 키**: 무게중심 오버레이. 조각별 무게중심 + 탑 전체 무게중심 + 접시의 지지 구간을 표시하고, 무게중심이 지지 구간을 벗어나면 `τ ≠ 0`으로 경고합니다
- 턴 제한 15초 (넘기면 자동 낙하 — 부스 회전율 확보)

작용하는 힘은 **중력뿐**이고, 안정 조건은 고전역학 그대로입니다.

| 개념 | 식 |
|---|---|
| 토크 | `τ = r × F` → 크기 `τ = d·mg` (d = 지지점에서 무게중심까지의 수평거리) |
| 정적 평형 | `ΣF = 0` 이고 `Στ = 0` |
| 안정 조건 | 무게중심의 수평 투영이 지지 구간(두 접촉점 사이) 안에 있을 때 |
| 무게중심·관성모멘트 | 콜라이더 다각형에서 적분으로 산출 — 신발끈 공식 `A = ½Σ(xᵢyᵢ₊₁ − xᵢ₊₁yᵢ)` |
| 접촉 해석 | 순차 충격량법(projected Gauss-Seidel) + 쿨롱 마찰 `|λt| ≤ μ·λn` |

**모양이 곧 성격입니다.** 밸런스 수치를 따로 조정하지 않고 실루엣으로 난이도를 만들었습니다.

| 음식 | 성격 | 음식 | 성격 |
|---|---|---|---|
| 호떡 | 넓고 평평 — 최고의 받침 | 계란후라이 | 아주 넓지만 노른자가 걸림 |
| 만두 | 밑면이 평평해 잘 쌓임 | 닭다리 | 무거워서 아래를 짓누름 |
| 김치 | 밑동이 넓어 가장 안정적 | 소떡소떡 | 가장 길다 — 걸치기의 명수 |
| 가래떡 | 긴 막대 — 기둥·다리로 | 군고구마 | 휘어서 어느 쪽으로도 안 눕음 |
| 붕어빵 | 비대칭 — 꼬리가 걸림 | 김밥 | 동그래서 잘 굴러감 — 최악 |

난수는 다음 음식 뽑기에만 씁니다. "똑같이 놓은 것 같은데 결과가 다른" 느낌은 난수가 아니라 접촉 해석의 **초기조건 민감성(카오스)**에서 나옵니다.

## 스프라이트 파이프라인

세 게임의 적·장애물·음식은 전부 **픽셀아트 K-푸드 스프라이트 12종**입니다.
원본은 장당 1~2MB(합계 15MB)라 그대로 쓸 수 없어, 빌드 스크립트로 가공합니다.

```
assets-src/*.png                 원본 (합계 15MB)
      ↓  node scripts/build-sprites.cjs
public/sprites/*.png             게임이 불러오는 파일 (합계 281KB)
src/games/spriteManifest.ts      크기 + 실루엣에서 뽑은 충돌 도형
```

스크립트가 하는 일 — 의존성 없이 순수 Node로 PNG를 직접 디코드/인코드합니다.

1. **배경 글로우 제거** — 원본에 반투명 어두운 후광이 깔려 있어 알파 임계값(60) 미만은 버립니다
2. **크롭 + 축소** — 실제 그림 영역만 잘라 최대 132px로. 프리멀티플라이드 박스 평균이라 가장자리에 검은 테가 생기지 않습니다
3. **충돌 도형 추출** — 알파 실루엣에서 볼록 껍질(Andrew monotone chain)을 뽑아 10점으로 단순화. **보이는 모양과 부딪히는 모양이 같습니다**
4. **비스듬한 것 눕히기** — 핫도그·소떡소떡·양념치킨은 원본이 30~40° 기울어 그려져 있어 실루엣 바닥이 뾰족합니다. 알파 실루엣의 2차 모멘트로 주축 각도를 재서 그만큼 회전시켜 눕힙니다
5. **바닥·윗면 평탄화** — 3/4 시점이라 여전히 바닥이 둥근 것들은 접점이 한 점뿐이라 무엇을 올려도 굴러떨어집니다. 폭의 34%가 평평해질 때까지만(높이의 16% 이내) 얕게 깎아 설 자리를 만듭니다

이 두 단계로 조각이 그림 아래로 파묻혀 보이는 양이 최대 8.3px → 2.0px로 줄었고, 안착 각도도 최대 -54°에서 전부 0°가 됐습니다.

이미지가 아직 안 왔거나 로드에 실패하면 모든 그리기 함수가 `false`를 돌려주고, 호출 측이 **기존 벡터 그림으로 넘어갑니다.** 부스에서 파일 하나가 안 받아져도 게임은 계속 돌아갑니다.

| 게임 | 쓰이는 곳 |
|---|---|
| K-푸드 타워 | 쌓는 음식 12종 전부 |
| K-푸드 합치기 | 진화 체인 12단계 전부 (구슬 안에 담아 그림) |
| K-푸드 사격 | 만두(잡졸) · 김밥(빠른놈) · 컵떡볶이(탱커) · 불닭(보스) |
| 네온 러너 | 컵라면(점프) · 컵떡볶이 3단(2단 점프) · 만두(숙이기) · 김밥(낮은 천장) |
| 벡터 스트라이크 | 만두(잡몹A) · 10원빵(잡몹B) · 컵라면(발사기) · 핫도그(돌진병) · 떡볶이(중간보스) · 불닭(최종보스) |

러너는 **히트박스를 그대로 두고 그림만 채워 넣어** 난이도가 바뀌지 않았고, 슈팅은 스프라이트의 짧은 쪽을 판정 지름(2r)에 맞춰 히트박스를 항상 덮게 그립니다.

**적과 아이템 구분** — 음식 스프라이트를 그대로 쓰면 "먹는 것"으로 보여서 적인지 아이템인지 헷갈립니다. 그래서 적은 전부 **붉은 열기 + 회전하는 락온 링**을 두르고(돌진병은 궤적까지), 강화 아이템은 아우라 없이 **원래의 청록 캡슐**을 그대로 씁니다. 색 언어 자체를 갈라 놓아 한눈에 구분됩니다.

### 🫧 K-푸드 합치기 (`/merge`)
같은 음식끼리 닿으면 다음 단계로 **진화**하는 물리 퍼즐. 상자가 넘치면 끝이고 제한시간은 없습니다.

- **조작**: 마우스 또는 `←→` 조준, 클릭·`SPACE` 놓기
- **진화 12단계**: 10원빵 → 만두 → 김밥 → 소떡소떡 → 핫도그 → 양념치킨 → 컵라면 → 컵떡볶이 → 불닭 → 김치 → 라면 → **떡뽁이**
- 떨어지는 것은 **앞 5단계에서만** 나옵니다. 큰 음식은 오직 합쳐서만 만들 수 있습니다
- 최종 단계 둘을 합치면 **사라지면서** 큰 보너스 — 자리를 비워주는 보상입니다

**왜 구슬에 담았나** — 이 장르는 모든 조각이 원이어야 성립합니다(굴러서 틈을 메워야 하므로). 그런데 김밥(비율 3.2)·핫도그(3.7)처럼 길쭉한 스프라이트가 많아 원 판정에 그대로 넣으면 그림과 판정이 어긋납니다. 그래서 음식을 유리구슬 안에 담았습니다 — **구슬이 곧 충돌 원**이라 둘이 정확히 일치합니다. 구슬 색은 음식 고유색이 아니라 **이웃 단계끼리 최대한 달라 보이도록** 따로 배열했습니다 (붉은 음식이 몰려 있어 고유색을 쓰면 단계 구분이 안 됩니다).

| 개념 | 값 |
|---|---|
| 점수 | 삼각수 `Tₙ = n(n+1)/2` — 등차면 큰 걸 만들 이유가 없고, 지수면 후반이 폭주 |
| 반지름 성장비 | 1.19 (면적비 1.416) → **합칠 때마다 약 29%의 공간이 생긴다** |
| 최종 단계 1개의 가치 | 10원빵 2,048개 · 합치기 2,047번 · 총 8,100점 |

성장비가 √2면 면적이 정확히 2배라 합쳐도 공간 이득이 0입니다. 쌓이는 속도와 비워지는 속도의 줄다리기가 이 게임 재미의 전부라, **상자 크기와 성장비는 감이 아니라 엔진을 돌려 정했습니다.**

```
상자 폭 280~430 × 성장비 1.17~1.21 교차 측정 (판당 12회)
  430폭 → 12판 중 6판이 안 죽음 (합쳐서 생기는 공간이 쌓이는 속도를 이김)
  1.17  → 300회 넘게 떨어뜨려야 끝남
  1.21  → 최종 지름이 상자의 76%까지 커져 후반이 답답
  → 확정: 상자 300×440, 성장비 1.19, 기본 반지름 15
```

**등급도 같은 방식으로** 정했습니다. 서로 다른 AI 3종을 24판씩 돌린 점수 분포입니다.

| AI | 점수(최저~최고) | 중앙 | 도달 단계 | 낙하 수 |
|---|---|---|---|---|
| 막 놓는 초보 | 493 ~ 1,027 | 728 | 컵떡볶이 | 122 |
| 같은 것 위에 놓는 평균 | 1,118 ~ 1,968 | 1,400 | 불닭 | 169 |
| 큰 것을 벽으로 모는 요령파 | 1,363 ~ 3,194 | 1,902 | 김치 | 209 |

→ **S 2,500 / A 1,700 / B 1,100 / C 500.** 초보는 C, 평균은 B, 잘하면 A, S는 드물게 나옵니다.

**구현에서 진짜 어려운 곳은 물리가 아니라 합치기입니다.** A가 같은 프레임에 B·C 양쪽과 닿으면 A가 두 번 소비돼 음식이 복제됩니다. 그래서 충돌 순간에는 예약만 하고 물리 스텝이 끝난 뒤 처리하며, 잠든 몸체끼리는 `collisionStart`가 다시 오지 않으므로 0.2초마다 같은 단계끼리 겹쳤는지 훑는 **안전망**을 따로 돌립니다. 검증은 보존 법칙으로 했습니다 — 떨어뜨린 총량(1단계 환산)이 판 위의 총량과 정확히 일치하는지 16판을 돌려 확인했고, 전부 차이 0이었습니다.

### 🥢 K-푸드 사격 (`/arrow`)
좌우로만 움직이는 자동 발사 슈팅. 내려오는 **게이트**를 어느 쪽으로 지나갈지 골라 화력을 키웁니다.

- **조작**: 마우스 또는 `←→` — 전진도 발사도 자동
- **게이트 8종**: 젓가락 +2 / 젓가락 ×1.6 / 공격력 +25% / 연사 +15% / 관통 +1 / 최대 체력 +30 / 회복 +50% / 보호막 +1
- **죽는 조건**: 체력 0. 못 죽인 적이 아래로 내려오면 체력이 깎입니다 — **화력이 모자라면 죽는 구조**
- 5구간마다 보스, 제한시간 없음

**이 장르의 성패는 방정식 하나에 달려 있습니다.**

```
화력 = 젓가락 수 N × 기본데미지 × 공격배수 M × 연사 R × 관통보너스(P)
적 체력 H(w) = 목표교전시간 × 기준선(w),   기준선(w) = 화력₀ · G^w
```

화력이 빠르면 후반이 시시해지고, 적 체력이 빠르면 아무리 강화해도 제자리라 강화하는 맛이 없습니다. 그래서 둘을 같은 지수로 묶되, **기준선 G를 "게이트를 아무거나 고르는 사람"의 성장률에 맞췄습니다.** 게이트 뽑기를 4,000판씩 돌려 측정한 값입니다.

| 게이트 고르는 방식 | 24게이트 후 화력 | 게이트당 성장률 | 보스 교전시간 |
|---|---|---|---|
| 아무거나 | 91배 | 1.207 | 8~13초 |
| 공격만 | 191배 | 1.245 | 5~6초 |
| 균형 있게 | 303배 | 1.269 | **3.5초** |

→ `GROWTH = 1.215`. 잘 고른 사람은 기준선을 앞질러 적을 3배 빠르게 녹이고, 못 고른 사람은 뒤처져 적이 새어 나옵니다. **고르는 행위에 의미가 생깁니다.**

개수는 더하기(+2)와 곱하기(×1.6)를 섞었습니다. 더하기만 있으면 2→4는 2배지만 20→22는 1.1배라 후반에 성장이 멈추고, 곱하기만 있으면 폭주합니다. 적 피해는 **선형**으로만 키웁니다 — 체력은 골라야만 오르는데 피해가 지수로 커지면 아무도 못 버팁니다.

**등급도 전체 게임을 시뮬레이션해서 정했습니다.**

| AI | 점수 중앙 | 도달 구간 | 판 시간 | 기준선 대비 |
|---|---|---|---|---|
| 부스 손님 (겨냥은 하되 반응이 늦고 게이트를 안 읽음) | 2,597 | 14구간 | 2.1분 | **99%** |
| 요령 있는 사람 (아래 적 겨냥 + 좋은 게이트) | 13,946 | 24구간 | 3.4분 | 219% |

→ **S 20,000 / A 8,000 / B 3,000 / C 1,200.** 기준선 대비 99%는 우연이 아니라 설계대로 맞은 값입니다.

시뮬레이션이 배포 전에 버그 두 개를 잡았습니다. ① 한 볼리의 젓가락들이 id를 공유해 **한 볼리가 적을 한 번만 때렸습니다**(실효 화력 1/N). ② 보스 구간이 길어지면 게이트가 반복해서 열려 **무한 강화**가 됐습니다. 둘 다 그냥 배포됐을 문제입니다.

## 사운드

BGM·효과음 전부 **Web Audio API로 코드에서 실시간 합성** — 외부 음원 파일이 없어 저작권 문제가 없습니다.

- 16스텝 시퀀서(킥/하이햇/베이스/리드)로 BGM 생성, 룩어헤드 스케줄링으로 타이밍 안정
- 슈팅은 일반전·보스전 BGM 2곡이 상황에 따라 전환
- 상황별 효과음: 점프/2단점프/급강하/착지/마일스톤/충돌, 발사/명중/격추/보스폭발/피격/아이템/웨이브/보스경보
- 게임오버 시 **등급별 다른 징글**, 클리어 시 팡파레
- `M` 키로 음소거. 브라우저 정책상 첫 클릭·키 입력 이후부터 소리가 납니다

## 성능 · 현장 안정성

부스 PC 사양과 행사장 네트워크를 예측할 수 없으므로 다음을 넣어두었습니다.

- **적응형 화질** (`src/lib/perf.ts`): 실측 FPS가 낮으면 렌더 해상도를 자동으로 낮추고(픽셀 수 최대 1/4), 그래도 느리면 파티클·잔상 같은 부가 효과를 줄입니다. 여유가 생기면 되돌립니다.
- **`F` 키**: 현재 FPS와 렌더 배율 표시 (현장에서 성능 확인용)
- **오프라인 캐시** (`public/sw.js`): 한 번 로드하면 서비스 워커가 정적 자원을 캐시해, **와이파이가 끊겨도 게임이 계속 돌아갑니다.**
- **웹폰트 최소화**: 한글은 시스템 폰트를 사용해 수 MB짜리 웹폰트를 받지 않습니다. 라틴 디스플레이 폰트(Orbitron)만 외부에서 받고, 실패해도 폴백으로 즉시 렌더됩니다.
- 게임 화면에서는 배경 애니메이션이 멈추고, 캔버스 위 `backdrop-filter`를 제거해 매 프레임 배경 블러를 재계산하지 않습니다.
- 캔버스는 `alpha: false` 컨텍스트로 생성해 합성 비용을 줄였습니다.

### 난이도·등급 조정

각 엔진 파일 상단의 `CONFIG` 객체만 수정하면 됩니다.

```ts
// src/games/shooter.ts
const CONFIG = {
  grades: [{ min: 30000, label: 'S', ... }, ...],  // 등급 기준 점수
  lives: 3,
  finalWave: 15,        // 최종보스가 나오는 웨이브
  clearBonus: 5000,
  ...
};
```

리허설로 실제 점수 분포를 본 뒤 `grades`의 `min` 값을 조정하는 것을 권장합니다.
